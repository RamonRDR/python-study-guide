## Dónde pedir ayuda

Python Study Guide se mantiene como un proyecto educativo público. Las preguntas y los informes deben utilizar el canal que corresponda a su propósito.

| Necesidad | Canal recomendado |
|---|---|
| Contenido incorrecto o roto en el repositorio | Abre una issue de tipo **Bug report** |
| Sugerir un capítulo, ejemplo, ejercicio o mejora | Abre una issue de tipo **Content suggestion** |
| Corregir o mejorar una traducción | Abre una issue de tipo **Translation improvement** |
| Aprender a preparar una contribución | Lee la [guía de contribución](CONTRIBUTING.es.md) |
| Informar una vulnerabilidad | Sigue la [política de seguridad](SECURITY.es.md) y utiliza el canal privado indicado |
| Informar acoso u otro problema de conducta | Sigue el [código de conducta](CODE_OF_CONDUCT.es.md) y utiliza el canal privado indicado |

Las issues pueden escribirse en inglés, portugués de Brasil o español. Conserva las rutas del repositorio, el código, los comandos y los identificadores técnicos exactamente como aparecen.

## Qué cubre el soporte del proyecto

El soporte puede ayudar con:

- localizar o comprender material publicado en este repositorio;
- reproducir un ejemplo exactamente como está documentado;
- identificar errores, explicaciones poco claras o navegación rota;
- comprender los requisitos de contribución;
- proponer mejoras específicas conectadas con el roadmap;
- aclarar si una solicitud pertenece a este repositorio.

## Qué no cubre el soporte del proyecto

Este repositorio no ofrece:

- soporte urgente, garantizado o privado para preguntas comunes;
- realización de tareas escolares, universitarias, entrevistas o trabajos profesionales en nombre de otra persona;
- depuración de proyectos privados o no relacionados con la guía;
- recuperación de credenciales, soporte de cuentas o soporte oficial para GitHub, Python, OpenAI u otros productos;
- mentoría individual con plazos garantizados de respuesta;
- asesoramiento profesional especializado.

Las preguntas sobre productos externos deben dirigirse a sus canales oficiales de soporte y documentación.

## Cómo formular una pregunta útil

Una solicitud útil normalmente incluye:

- la ruta exacta del repositorio o una URL pública;
- qué intentas comprender o reproducir;
- qué esperabas que ocurriera;
- qué ocurrió de forma diferente;
- un ejemplo mínimo y seguro;
- la versión de Python y el sistema operativo cuando exista ejecución;
- los comandos y comprobaciones ya realizados;
- confirmación de que se eliminaron datos privados y propietarios.

No envíes proyectos privados completos cuando un pequeño ejemplo ficticio pueda demostrar el mismo problema.

## Expectativas de respuesta

El proyecto se mantiene con el mejor esfuerzo posible. Abrir una issue no garantiza un plazo de respuesta, una implementación ni la aceptación de la solución propuesta.

Las solicitudes podrán cerrarse cuando estén fuera del alcance, dupliquen trabajo existente, no tengan suficiente información pública para evaluarlas, contengan material confidencial o entren en conflicto con los estándares educativos y de seguridad del proyecto.

Los seguimientos respetuosos son bienvenidos. No se aceptan la presión repetida, los mensajes privados no solicitados ni los intentos de evitar el proceso público de revisión.
