# Como contribuir com o Python Study Guide

[🇺🇸 English](CONTRIBUTING.md) · [🇧🇷 Português](CONTRIBUTING.pt-BR.md) · [🇪🇸 Español](CONTRIBUTING.es.md)

Obrigado por ajudar a melhorar este projeto de aprendizagem.

## Princípios fundamentais

- Mantenha os identificadores do código e os nomes dos arquivos em inglês.
- Prefira explicações claras a textos excessivamente elaborados.
- Explique por que e quando utilizar um recurso, não apenas como utilizá-lo.
- Utilize exemplos originais criados para este repositório.
- Mantenha as três versões de idioma conceitualmente alinhadas.
- Nunca inclua dados confidenciais, proprietários ou pessoais.

## Fluxo de contribuição

1. Crie ou escolha uma issue que descreva a melhoria.
2. Crie uma branch específica a partir da `main`.
3. Faça commits pequenos e fáceis de revisar.
4. Atualize todos os documentos de idioma afetados.
5. Execute os exemplos e testes que foram alterados.
6. Abra um pull request explicando o que mudou e por quê.

## Nomes de branches

```text
feat/topic-name
docs/topic-name
fix/topic-name
test/topic-name
refactor/topic-name
```

Os nomes das branches devem permanecer em inglês para seguir o padrão internacional adotado pelo projeto.

## Mensagens de commit

Utilize mensagens curtas no estilo Conventional Commits:

```text
docs: add chapter about comments
feat: add string validation example
fix: correct average calculation
```

## Formato dos capítulos

Novos capítulos de aprendizagem devem abordar:

1. O que é
2. Por que existe
3. Sintaxe
4. Quando utilizar
5. Quando evitar
6. Como se conecta a outros recursos
7. Exemplo básico
8. Exemplo prático
9. Erros comuns
10. Exercício
11. Resumo para consulta rápida

## Idiomas

O inglês é o idioma padrão do repositório. As traduções para português brasileiro e espanhol devem preservar o mesmo significado técnico, sem exigir uma tradução literal palavra por palavra.

Ao alterar uma documentação traduzida, atualize todas as versões de idioma afetadas sempre que possível. Caso uma tradução não possa ser concluída no mesmo pull request, identifique claramente qual versão está faltando.

## Estilo do código

- Utilize nomes descritivos em inglês.
- Siga a PEP 8.
- Adicione type hints quando eles melhorarem a compreensão.
- Comente decisões, restrições e motivos que não sejam óbvios.
- Não comente um código que já se explica sozinho.

## Pull requests

Um pull request deve ser focado, fácil de revisar e livre de alterações não relacionadas. Capturas de tela podem ser incluídas quando o layout da documentação for afetado.

Antes de enviar, confirme que:

- os links funcionam corretamente;
- os exemplos executam conforme descrito;
- a terminologia está consistente;
- os documentos traduzidos continuam conceitualmente alinhados;
- nenhum material confidencial ou proprietário de terceiros foi incluído.
