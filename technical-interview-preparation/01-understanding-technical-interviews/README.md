## Purpose and process

A technical interview collects evidence about how you reason, implement, test and communicate. Hiring processes vary: a recruiter may discuss role expectations; a behavioral interview explores actual experiences; technical screening may use questions, code review or an exercise; a later conversation may discuss architecture or collaboration. Not every employer uses every stage.

Before an interview, ask about duration, tools, language, assessment criteria and whether documentation or AI is allowed. Do not assume the rules of one employer apply to another. Behavioral questions require truthful examples; technical questions require a clear explanation, not a memorized speech.

## A practical conversation

Suppose a fictional service needs to count eligible registrations. Ask what eligibility means, whether duplicates count, and what to return for empty input. Restate the agreed contract; give a concrete example; choose an approach; explain assumptions; test the result; discuss limitations. If a requirement is missing, ask instead of inventing it. If you do not know a term, say what you do know and how you would verify the missing detail. Avoid claiming that code ran when it did not.

## Independent practice

Explain a small program you wrote in two minutes: problem, inputs, decision, result, one test and one limitation. Ask a study partner for a requirement change and explain its effect. Check whether your explanation distinguishes evidence from assumptions.

**Quick reference:** clarify → reason → implement → verify → communicate.
